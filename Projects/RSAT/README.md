# RSAT Admin-Tools Install Package

Builds a small (~62 MB) self-contained folder that MECM uses as package
source to install a **fixed set of 9 administrative capabilities** on
Windows 11 — the RSAT tools an admin workstation / helpdesk actually uses,
plus the BitLocker recovery tools and the OpenSSH client. Works in two
deployment contexts:

- an **MECM OSD Task Sequence** step, applied to the offline OS image while
  still running in WinPE;
- a **direct MECM collection deployment** (Run Script or Package/Program),
  running in the full online OS.

The environment has no reliable path to Microsoft Update for Features on
Demand, so all source content comes from local media: the two
`..._CLIENT_LOF_PACKAGES_OEM.iso` files (Windows 11 22H2 build 22621 and
24H2 build 26100) kept in `media-archive/`. Each ISO is ~6–7 GB and carries
FOD cabs for far more than what is needed; this project extracts only the 9
required cabs.

---

## The 9 capabilities

| Capability | Tool |
|---|---|
| `Rsat.ServerManager.Tools` | Server Manager |
| `Rsat.FileServices.Tools` | File Services / DFS / storage tools |
| `Rsat.ActiveDirectory.DS-LDS.Tools` | AD DS and AD LDS tools (ADUC, etc.) |
| `Rsat.GroupPolicy.Management.Tools` | Group Policy Management Console |
| `Rsat.Dns.Tools` | DNS server tools |
| `Rsat.DHCP.Tools` | DHCP server tools |
| `Rsat.FailoverCluster.Management.Tools` | Failover Cluster Manager |
| `Rsat.BitLocker.Recovery.Tools` | BitLocker Drive Encryption Administration Utilities |
| `OpenSSH.Client` | OpenSSH client (`ssh.exe`) |

Language-neutral cabs only. The full list lives in `RsatCapabilities.psd1`
and is the single source of truth — the builder reads the cab names, the
installer reads the capability names. Every cross-capability dependency
(`BitLocker → AD`, `AD → ServerManager`, `FileServices → ServerManager`,
`FailoverCluster → FileServices`) is satisfied within the set.

Hyper-V management is **not** included — on Windows client it is an in-box
optional feature (`Microsoft-Hyper-V-Management-*`), not a capability, and
no cab for it exists on these ISOs.

## Building the package

Run on an admin workstation whenever an ISO is added or refreshed. Requires
only Windows PowerShell 5.1 (mounts ISOs via `Mount-DiskImage`).

```powershell
# Default: reads every *.iso in .\media-archive\, outputs .\RSAT-Install\
.\Build-RsatPackage.ps1

# Or point at specific ISOs / a different output folder
.\Build-RsatPackage.ps1 -IsoPath D:\iso\26100...OEM.iso -OutputPath C:\temp\RSAT-Install
```

Per ISO the builder parses the build number from the filename, mounts the
ISO read-only, **verifies all 9 cabs are present** (hard-fails naming any
that are missing), copies them into `LanguagesAndOptionalFeatures\<build>\`,
and dismounts. It then copies `Install-RSAT.ps1` + `RsatCapabilities.psd1`
into the output and writes `manifest.json`. Re-running rebuilds only the
affected build's subfolder. The whole `RSAT-Install\` folder is the MECM
package source — wiring it into an MECM Package / TS step is a manual step
in the ConfigMgr console.

## Deploying (`Install-RSAT.ps1`)

Ships inside `RSAT-Install\`. Detects its context and adapts:

| Context | Detection | Install target |
|---|---|---|
| WinPE / OSD task sequence | `MiniNT` registry key + `Microsoft.SMS.TSEnvironment` COM object | offline image at `%OSDTargetSystemDrive%` (`Add-WindowsCapability -Path`) |
| Full OS | neither present | running OS (`Add-WindowsCapability -Online`) |

It reads the target's `CurrentBuildNumber`, resolves the matching
`LanguagesAndOptionalFeatures\<build>\` folder (see **Supported builds**),
then installs the 9 capabilities — `ServerManager` → `FileServices` →
`ActiveDirectory` first so dependencies resolve — skipping any already
installed (`OpenSSH.Client` ships pre-installed on 24H2+). Always logs to
`C:\Windows\Temp\RSAT-Install\Install-RSAT_<timestamp>.log`; prints a
readable summary only when run interactively outside a task sequence.

```powershell
# Interactive check — installs nothing
.\RSAT-Install\Install-RSAT.ps1 -WhatIf

# Real install (elevated)
.\RSAT-Install\Install-RSAT.ps1
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | all 9 installed or already present |
| `3010` | installed, reboot required |
| `1` | one or more capabilities failed (including any the OS does not offer) |
| `2` | no source folder for this OS build |
| `3` | not elevated |

### Supported builds

| OS build | Source |
|---|---|
| 22621 (Win11 22H2) | `\22621\` |
| 22631 (Win11 23H2) | `\22621\` (alias — same servicing branch) |
| 26100 (Win11 24H2) | `\26100\` |
| 26200 (Win11 25H2) | `\26100\` (alias — same servicing branch) |
| anything else | none → exit `2` |

Aliases live in `BuildSourceMap` in `RsatCapabilities.psd1`. An exact
`<build>` subfolder always wins over an alias. An unmapped unknown build
fails fast — the script never guesses.

## Testing

```powershell
Invoke-Pester -Path .\RsatCapabilities.Tests.ps1,.\Build-RsatPackage.Tests.ps1,.\Install-RSAT.Tests.ps1 -Output Detailed
```

48 Pester tests over the pure decision/parsing logic (capability selection,
install ordering, build/alias resolution, cab verification, exit-code
selection, WinPE detection, run-context). The tests never mount an ISO,
load a real hive, or call a real DISM cmdlet.

**Before handoff to helpdesk**, validate the real DISM path manually (no
task in this repo runs `Add-WindowsCapability` for real automatically):

1. On a real 22H2/23H2/24H2/25H2 machine — run `Install-RSAT.ps1` elevated,
   confirm exit `0`/`3010` and that the tools + `ssh.exe` appear.
2. Wire `RSAT-Install\` into an MECM Package + a test OSD task sequence step
   in WinPE, confirm the offline path works. This needs the ConfigMgr boot
   image to include the storage/scripting WinPE optional components
   (present when PowerShell support is enabled on it).

## Maintenance

- **New Windows release on an existing branch** (e.g. a future 26xxx build):
  add one line to `BuildSourceMap`.
- **New servicing branch / new ISO**: drop the `..._CLIENT_LOF_PACKAGES_OEM.iso`
  into `media-archive/`, re-run `Build-RsatPackage.ps1`.
- **Add / remove / rename a capability**: edit `RsatCapabilities.psd1`
  (one file); the builder's "all 9 cabs present" check will flag a renamed
  cab stem loudly on the next build.

Design spec and implementation plan: `docs/superpowers/`.
