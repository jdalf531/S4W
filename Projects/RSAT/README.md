# RSAT Admin-Tools Install Package

Builds a self-contained folder (~286 MB per Windows build) that MECM uses
as package source to install a **fixed set of 9 administrative
capabilities** on Windows 11 — the RSAT tools an admin workstation /
helpdesk actually uses, plus the BitLocker recovery tools and the OpenSSH
client. Works in two deployment contexts:

- an **MECM OSD Task Sequence** step, applied to the offline OS image while
  still running in WinPE;
- a **direct MECM collection deployment** (Run Script / Package / Application),
  running in the full online OS.

The environment has no reliable path to Microsoft Update for Features on
Demand, so all source content comes from local media: the Windows 11
"Languages and Optional Features" ISOs kept in `media-archive/` (currently
22H2 / build 22621, 24H2 / build 26100, and 26H1 / build 28000). Each ISO
is ~6–7 GB and carries ~4000 FOD cabs; this project extracts only the ~660
that belong to the 9 capabilities (every architecture and language) plus
the FoD `metadata\` folder, one `<build>` folder per ISO.

---

## The 9 capabilities

| Capability | Tool |
|---|---|
| `Rsat.ServerManager.Tools` | Server Manager |
| `Rsat.FileServices.Tools` | File Services / DFS / storage tools |
| `Rsat.ActiveDirectory.DS-LDS.Tools` | AD DS and AD LDS tools (ADUC, etc.) |
| `Rsat.GroupPolicy.Management.Tools` | Group Policy Management Console |
| `Rsat.Dns.Tools` | DNS server tools |
| `Rsat.DHCP.Tools` | DHCP server tools |
| `Rsat.FailoverCluster.Management.Tools` | Failover Cluster Manager |
| `Rsat.BitLocker.Recovery.Tools` | BitLocker Drive Encryption Administration Utilities |
| `OpenSSH.Client` | OpenSSH client (`ssh.exe`) |

The full list lives in `RsatCapabilities.psd1` (single source of truth —
builder matches cabs by stem prefix, installer uses the capability names).
For each capability, **every** cab for its stem ships — all architectures
(`amd64`, `wow64`) and all ~40 languages. The RSAT FoD is a multilingual
package; a language-neutral subset fails to install (`0x800f0955`). Every
cross-capability dependency (`BitLocker → AD`, `AD → ServerManager`,
`FileServices → ServerManager`, `FailoverCluster → FileServices`) is
satisfied within the set.

Hyper-V management is **not** included — on Windows client it is an in-box
optional feature (`Microsoft-Hyper-V-Management-*`), not a capability, and
no cab for it exists on these ISOs.

```
Projects/RSAT/
├── RsatCapabilities.psd1          – the 9-capability table + BuildSourceMap; edit here only
├── RsatCapabilities.Tests.ps1     – structural validation of the .psd1
├── Build-RsatPackage.ps1          – run manually by an admin; assembles RSAT-Install/
├── Build-RsatPackage.Tests.ps1    – Pester tests for the builder's pure logic
├── Install-RSAT.ps1              – the deployed installer; ships inside RSAT-Install/
├── Install-RSAT.Tests.ps1        – Pester tests for the installer's pure logic
├── media-archive/                – the original LOF ISOs (git-ignored) + README
└── RSAT-Install/                 – generated by the builder (git-ignored)
    ├── Install-RSAT.ps1
    ├── RsatCapabilities.psd1
    ├── manifest.json             – per-build source ISO + cab count/size + UTC timestamp
    └── LanguagesAndOptionalFeatures/
        ├── 22621/                – ~660 cabs + metadata\ (~286 MB, one folder per ISO)
        ├── 26100/                – ~660 cabs + metadata\

```

Each `<build>\` folder holds, for the 9 capability stems, **every** cab the
ISO carries — all architectures and languages — plus the `metadata\`
Component Database. That's the exact set DISM needs to resolve and install
the (multilingual) capabilities offline with `-LimitAccess`.

Design spec and implementation plan live with the other projects' docs at
the repo root: `docs/superpowers/specs/2026-08-18-rsat-install-package-design.md`
and `docs/superpowers/plans/2026-08-31-rsat-admin-tools-package.md`.

## Building the package

Run on an admin workstation whenever an ISO is added or refreshed. Requires
only Windows PowerShell 5.1 (mounts ISOs via `Mount-DiskImage`).

```powershell
# Default: reads every *.iso in .\media-archive\, outputs .\RSAT-Install\
.\Build-RsatPackage.ps1

# Or point at specific ISOs / a different output folder
.\Build-RsatPackage.ps1 -IsoPath D:\iso\26100...OEM.iso -OutputPath C:\temp\RSAT-Install
```

Per ISO the builder mounts it read-only, requires the neutral `~amd64~~`
FeaturePackage cab for all 9 capabilities and the `metadata\` folder to be
present (hard-fails otherwise), **reads the OS build from a cab's own
package manifest** (`10.0.<build>.<rev>` — the value DISM matches against,
so the ISO filename format is irrelevant), then copies into
`LanguagesAndOptionalFeatures\<build>\`: every cab matching each capability
stem (all arches, all languages) **plus the whole `metadata\` folder**. It
then copies `Install-RSAT.ps1` + `RsatCapabilities.psd1` into the output and
writes `manifest.json`.
Re-running rebuilds only the affected build's subfolder. The whole
`RSAT-Install\` folder is the MECM package source — wiring it into an MECM
Application / Package / TS step is a manual step in the ConfigMgr console.

## Deploying (`Install-RSAT.ps1`)

Ships inside `RSAT-Install\`. Detects its context and adapts:

| Context | Detection | Install target |
|---|---|---|
| WinPE / OSD task sequence | `MiniNT` registry key + `Microsoft.SMS.TSEnvironment` COM object | offline image at `%OSDTargetSystemDrive%` (`Add-WindowsCapability -Path`) |
| Full OS | neither present | running OS (`Add-WindowsCapability -Online`) |

It reads the target's `CurrentBuildNumber`, resolves the matching
`LanguagesAndOptionalFeatures\<build>\` folder (see **Supported builds**),
then installs the 9 capabilities — `ServerManager` → `FileServices` →
`ActiveDirectory` first so dependencies resolve — skipping any already
installed (`OpenSSH.Client` ships pre-installed on 24H2+). Always logs to
`C:\Windows\Temp\RSAT-Install\Install-RSAT_<timestamp>.log`; prints a
readable summary only when run interactively outside a task sequence.

```powershell
# Interactive check — installs nothing
.\RSAT-Install\Install-RSAT.ps1 -WhatIf

# Real install (elevated)
.\RSAT-Install\Install-RSAT.ps1
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | all 9 installed or already present |
| `3010` | installed, reboot required |
| `1` | one or more capabilities failed (including any the OS does not offer) |
| `2` | no source folder for this OS build |
| `3` | not elevated |

### Supported builds

| OS build | Source | Notes |
|---|---|---|
| 22621 (Win11 22H2) | `\22621\` | from `22621.…OEM.iso` |
| 22631 (Win11 23H2) | `\22621\` | alias — Microsoft's 22621 ISO covers 22H2 + 23H2 |
| 26100 (Win11 24H2) | `\26100\` | from `26100.…OEM.iso` |
| 26200 (Win11 25H2) | `\26100\` | alias — Microsoft's 26100 ISO covers 24H2 + 25H2 |
| 28000 (Win11 26H1) | `\28000\` | from `mul_…26h1…dvd_….iso` |
| anything else | none → **exit `2`** | get that release's LOF ISO, rebuild |

Microsoft ships **one LOF ISO per release pair** — the 22621 ISO covers
22H2 and 23H2, the 26100 ISO covers 24H2 and 25H2 ([MS Learn — AVD language
packs](https://learn.microsoft.com/en-us/azure/virtual-desktop/windows-11-language-packs)).
The `BuildSourceMap` in `RsatCapabilities.psd1` records those aliases; an
exact `<build>\` folder always wins over an alias.

On a machine patched past the ISO's RTM build, installing with `-LimitAccess`
can't fetch the LCU-level FoD top-up, so RSAT installs at RTM binary level
and self-flags for reconciliation at the next cumulative update
(`0x800f0912` in CBS.log). Functionally fine for admin tools.

## Testing

```powershell
Invoke-Pester -Path .\RsatCapabilities.Tests.ps1,.\Build-RsatPackage.Tests.ps1,.\Install-RSAT.Tests.ps1 -Output Detailed
```

51 Pester tests over the pure decision/parsing logic (capability selection,
install ordering, build detection from a package manifest, alias
resolution, per-stem cab selection, exit-code selection, WinPE detection,
run-context). The tests never mount an ISO, load a real hive, or call a
real DISM cmdlet.

**Validate the real DISM path per Windows build** — the Pester tests do not
call `Add-WindowsCapability`, so each `<build>\` folder must be proven on a
matching machine (`0x800f081f` = missing `metadata\`; `0x800f0955` =
missing language cabs):

1. On a machine of that build (or its aliased partner) — run
   `Install-RSAT.ps1` elevated, confirm exit `0`/`3010` and that the tools
   + `ssh.exe` appear. If it exits `2`, there's no matching folder — get
   that release's LOF ISO, drop it in `media-archive\`, rebuild (and add a
   `BuildSourceMap` entry if it shares an ISO with another release).
2. Wire `RSAT-Install\` into an MECM Package + a test OSD task sequence step
   in WinPE, confirm the offline path works. This needs the ConfigMgr boot
   image to include the storage/scripting WinPE optional components
   (present when PowerShell support is enabled on it).

## Maintenance

- **Any new Windows release**: get that release's "Languages and Optional
  Features" ISO (Microsoft ships one per release *pair* — check the
  [AVD language-packs doc](https://learn.microsoft.com/en-us/azure/virtual-desktop/windows-11-language-packs)
  for which ISO covers which versions), drop it in `media-archive/` (any
  filename), re-run `Build-RsatPackage.ps1` — it reads the build from the
  cab manifests and creates the `<build>\` folder automatically. If the
  release shares an ISO with another (like 23H2↔22H2, 25H2↔24H2), add a
  `BuildSourceMap` alias in `RsatCapabilities.psd1`.
- **Add / remove / rename a capability**: edit `RsatCapabilities.psd1`
  (one file); the builder's FeaturePackage-present check will flag a renamed
  cab stem loudly on the next build.
